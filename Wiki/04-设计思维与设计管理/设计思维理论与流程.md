# 设计思维——理论与流程

## 核心定义

**设计思维**（Design Thinking）本质上是一种**以人为本的问题解决方法**。这里的"设计"是广义设计——以探索人的需要为出发点，创造出符合其需要的解决方案。

与传统问题解决路径的本质区别：

| 维度 | 传统路径 | 设计思维 |
|------|---------|---------|
| 问题定义 | 直接看到问题→想解决办法 | 深入理解问题→重新定义问题 |
| 解决过程 | 快速锁定方案 | 探索多种可能性→选择最优→反复测试 |
| 认知风险 | 认知偏差导致"解决了错误的问题" | 通过同理心环节降低认知偏差 |

## 设计思维的五阶段流程

```
[同理心] → [定义] → [头脑风暴] → [原型] → [测试]
Empathize    Define    Ideate      Prototype   Test
```

1. **同理心（Empathize）**：深入了解用户的真实需求、感受和行为
2. **定义（Define）**：整合洞察，明确要解决的核心问题（POV陈述）
3. **头脑风暴（Ideate）**：发散思维，探索尽可能多的解决方案
4. **原型（Prototype）**：低成本快速制作可测试的方案模型
5. **测试（Test）**：通过用户反馈验证、迭代改进

## 发散与汇聚

设计思维的核心操作模式：

```
发散（Diverge）── 尽量拓宽可能性 ──→ 汇聚（Converge）── 聚焦最优解
```

问题与解决方法之间保留了足够的空间，过程没有标准答案。

## 换位思考（同理心）

认知偏差理论指出：人们会经常歪曲、遗漏、忽视或低估周围信息，而这些信息可能是理解问题的重要线索。设计思维通过强制性的同理心练习（用户访谈、田野观察）来克服这种偏差。
